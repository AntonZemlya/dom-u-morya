# R2B: локальный Publisher «Дома у моря»

Это приёмка и репетиция переключения в отдельной временной копии сайта. Команда намеренно принимает только непосредственный дочерний каталог системного temp с префиксом `dom-publisher-` и HTTP `127.0.0.1`. Обходного флага для production нет. Установка на хостинг, смена Cron, живой источник, SMTP, доставка заявок, merge и deploy не выполнялись и требуют отдельного решения владельца.

## Воспроизведение координатором

Нужны Python 3, Node 22, PHP, Playwright и Chromium. Для PHP-контракта отдельно используется PHP 8.4. Все npm-зависимости этой работы установлены только в `/private/tmp/dom-publisher-deps-hzMeAC`; `node_modules` в worktree во время теста был временной ссылкой, не входит в Git. Аналогично renderer R2A находится во временном checkout. Воспроизводимая установка зависимостей сайта:

```sh
cd /Users/azm1982/.codex/worktrees/6705/dom-u-morya
R2B_DEPS=$(mktemp -d /private/tmp/dom-publisher-deps-XXXXXX)
cp package.json package-lock.json "$R2B_DEPS/"
npm ci --prefix "$R2B_DEPS" --ignore-scripts --no-audit --no-fund
ln -s "$R2B_DEPS/node_modules" node_modules
```

Если зависимости и Chromium уже доступны, повторная установка не нужна. Для чистого checkout R2A выполните `npm ci --prefix /private/tmp/rpm-r2a-acceptance/renderer --ignore-scripts --no-audit --no-fund`. Не меняйте R2A во время прогона: fixture проверяет полный HEAD и отсутствие рабочего diff.

Полная локальная проверка, включая скачивание трёх PDF штатным JS:

```sh
export PATH="/private/tmp/dom-u-morya-pagespeed-repo/toolchain/php@8.4/8.4.27_1/bin:$PATH"
R2A_REPO=/private/tmp/rpm-r2a-acceptance python3 -B ops/test_catalog_publisher.py
python3 -B tests/r2b_e2e.py \
  --r2a-repo /private/tmp/rpm-r2a-acceptance \
  --output /private/tmp/dom-publisher-coordinator-evidence
npm run ci:fast
/private/tmp/dom-u-morya-pagespeed-repo/toolchain/php@8.4/8.4.27_1/bin/php tests/lead-contract.php
```

Runner использует настоящий HTTP-адаптер и exporter R2A с loopback-фикстурой. A содержит 26 лотов, включая публичный оригинал SVG `026ef1ab1116319eafed3c5a65c9f3c24034c4d4bb1d17138826dec2ee19cb1d`. B меняет цену `900001` с 7 000 000 на 7 010 000 и удаляет `900026`; `900002` сохраняет цену 7 000 000. C подтверждает те же данные B позднее: нативный SHA сохраняется, SHA пакета/подтверждения меняется. Остальные данные синтетические.

По умолчанию время подтверждения равно текущему UTC минус 60 секунд. Можно задать `--checked-at YYYY-MM-DDTHH:MM:SSZ`, а для unittest — `R2B_CHECKED_AT`. Проверка свежести никогда не отключается: исторический пакет через 36 часов пригоден для проверки байтов, но новая установка должна отказать. Для дальнейшей сквозной проверки создайте новые подтверждения.

Точные независимые ожидания и существующие каталоги последнего зафиксированного прогона находятся в `review/r2b/e2e/fixtures.json`. Использование уже созданных пакетов без повторного генератора:

```sh
python3 -B tests/r2b_e2e.py \
  --fixtures /Users/azm1982/.codex/worktrees/6705/dom-u-morya/review/r2b/e2e/fixtures.json \
  --output /private/tmp/dom-publisher-coordinator-replay
```

`fixtures.json` — отдельная доверенная запись ожидаемых SHA, а не значение, извлечённое публикатором из самого пакета. Runner передаёт `directory` и `package` отдельными аргументами. `e2e.json` и `browser.json` содержат точные команды, временный home, URL и итоговые статусы. PHP-процесс после теста остановлен; пакеты и home остаются для инспекции. Для нового сервера/нового home повторите runner, а не используйте старый порт из отчёта.

## Интерфейс приёмки и переключение

Только проверка пакета, без записи в сайт:

```sh
python3 -B ops/catalog_publisher.py verify --package "$PACKAGE_DIR" --sha "$EXPECTED_MANIFEST_SHA"
```

`EXPECTED_MANIFEST_SHA` — SHA256 точных байтов `manifest.json`, полученный отдельным доверенным каналом. Нативная версия — SHA256 точных байтов `private/snapshots/<native_sha>.json`. Проверяются schema/format/namespace, точное множество файлов и каталогов, отсутствие symlink/hardlink, владелец, приватные режимы, размеры, все digest, ID/цены/адреса, московская дата, время подтверждения, привязки SVG/WebP и полное совпадение производных поверхностей с результатом штатного JS-генератора. Новый WebP ограничен политикой R2A; SVG проверяется allowlist без исполнения содержимого.

Передача владения действующим локальным legacy-каталогом:

```sh
python3 -B ops/catalog_publisher.py owner --home "$LOCAL_HOME" --url "$LOCAL_URL" \
  --expect "$CURRENT_NATIVE_SHA" --owner publisher
python3 -B ops/catalog_publisher.py install --home "$LOCAL_HOME" --url "$LOCAL_URL" \
  --expect "$CURRENT_NATIVE_SHA" --package "$PACKAGE_DIR" --sha "$EXPECTED_MANIFEST_SHA"
```

Для первого private-каталога после bundled-сайта: `install ... --expect empty`. E2E создаёт правильную структуру `LOCAL_HOME/domains/zhk-dom-umorya.ru` автоматически. Используйте `status --home ... --url ...` для контрольного GET/HEAD и отдельного `trust_loss`; код 3 означает неподтверждённый каталог, 2 — конфликт/ошибку, 0 — успешную операцию.

Порядок под lock: `catalog-sync-v1/sync.lock`, затем `.dom-u-morya/manager-v1/lock` — те же пути и порядок, что у worker. Ожидаемая база перечитывается внутри обеих блокировок. До takeover/install/restore проверяются точные байты уже установленного `runtime/scripts/catalog_sync.py` и `catalog-cron.sh`. Неподготовленный старый runtime получает `installed_worker_requires_guarded_migration`; одно поле `publisher_owner` не считается достаточной защитой. Отсутствие runtime допустимо только в новой локальной установке без старого worker. Обновление реального runtime и изменение расписания этим PR не выполняются.

В publisher-режиме guarded worker отказывается от `run`, `restore`, `interrupted` и `mail-test` до изменения состояния/доставки. Служебные поля worker, `etags`, `outbox`, `history_events`, история и неизвестные расширения сохраняются. Меняются только проекция чтения и поля `publisher_*`; очередь не отправляется. Незавершённый legacy-запуск или pending-публикация блокирует новое независимое переключение.

Сначала сохраняются неизменяемые ресурсы и снимок (0600, каталоги 0700 вне document root), затем приватная запись транзакции с прежней проекцией и digest всех прежних ресурсов. После fsync меняется один `state.json`: временный файл в той же директории, fsync файла, rename, fsync директории. Проверяются GET и HEAD локального `index.php`, SHA шаблона, статус, версия и browser data; успешная проверка снимает pending-маркер. Повтор тех же байтов успешен, а коллизия под существующим именем блокируется. Старые ресурсы автоматически не удаляются.

## Старое и новое превью

Старый URL `api/catalog-plan.php?file=<svg_sha>.preview.webp` продолжает читать `media/<svg_sha>.preview.webp` без изменения байтов. Новый URL содержит `preview=<webp_sha>&file=<svg_sha>.svg`; существующий JS меняет только конечное `.svg` на `.preview.webp`. Новый WebP устанавливается как `media/previews/<webp_sha>.webp` и проверяется по своему SHA при каждой выдаче; SVG сохраняет прежнюю проверку собственного SHA. Пакет транспорта по контракту всё ещё содержит `private/media/<svg_sha>.preview.webp`.

Старые пакеты без параметра preview поддерживаются, но при другой кодировке существующего WebP под тем же старым именем получают отказ, сохраняя рабочую версию. Для исторических уже установленных VP8L-превью действует отдельная ограниченная проверка RIFF/chunk/размеров/version и сохранённые digest; строгая проверка новых входных пакетов не расширяется. Регрессия поднимает настоящий legacy bootstrap из 28 отслеживаемых лотов, 60 SVG/VP8L, проверяет разные SHA старого/нового WebP, обе HTTP-выдачи и SVG, затем восстановление и offline-возврат legacy worker.

## Потеря подтверждения и 409

Неудачная или несогласованная установка не продвигает время подтверждения. Истечение доверия через 36 часов действует непосредственно в PHP. Отдельный сигнал недоступности источника:

```sh
python3 -B ops/catalog_publisher.py invalidate --home "$LOCAL_HOME" --url "$LOCAL_URL" \
  --expect "$CURRENT_NATIVE_SHA" --expect-package "$CURRENT_CONFIRMATION_PACKAGE_SHA"
python3 -B ops/catalog_publisher.py status --home "$LOCAL_HOME" --url "$LOCAL_URL"
```

`invalidate` под обеими блокировками сохраняет `active`, `checked_at` и `published_checked_at`, устанавливает `source_ok=false` и отдельную метку причины/времени. Идентичный повтор не меняет состояние. Сравнивается и нативный SHA, и SHA текущего пакета: запоздалый отказ B после нового подтверждения C с тем же нативным SHA получает `confirmation_conflict` и не лишает C доверия. Повтор B не восстанавливает подтверждение; для этого нужен новый принятый пакет с более поздним checked_at.

Заявки тестируются только через изолированный вызов `DomLead\validate` на синтетических полях, без `accept`, config, почты и API доставки. При приватном каталоге запрос выбранного лота/расчёта должен содержать `catalogVersion`, совпадающий со всем текущим снимком. Старая версия даёт 409 даже при неизменной цене выбранного лота. Также 409 дают старая цена, выбывший ID и неподтверждённый каталог. Bundled-релиз без private state сохраняет прежний контракт; его открытая вкладка после подключения private-каталога получает требование обновления. Штатный PDF проверяет HEAD перед скачиванием; в доказательствах есть фактические PDF выбранного `900002` за 7 000 000 ₽, запрет повторного PDF старой вкладки и запрет при утрате подтверждения.

## Восстановление

```sh
python3 -B ops/catalog_publisher.py restore --home "$LOCAL_HOME" --url "$LOCAL_URL" \
  --expect "$EXPECTED_CURRENT_NATIVE_SHA"
```

Восстанавливается предыдущая рабочая версия из её приватной транзакции. До переключения проверяются все прежние digest, медиа и совместимость PHP render; отсутствие входного каталога пакета этому не мешает. Перед откатом сравнивается весь ожидаемый объект текущего состояния, включая служебные расширения. При стороннем изменении — `rollback_conflict`, без записи. Ручной откат завершённой публикации выставляет `source_ok=false`: он не создаёт нового подтверждения источника. Повтор восстановления распознаётся; для первой установки возможен безопасный возврат к bundled/empty.

| Место остановки | Состояние и действие |
| --- | --- |
| До смены state | Сайт продолжает прежнюю версию; повторить ту же install с той же независимой SHA и исходным expect. Незавершённые неизменяемые файлы не включены в выдачу. |
| После смены state, до проверки | В state есть `publisher_pending`; повтор того же пакета проверит HTTP и завершит транзакцию, либо явно выполните restore с ожидаемым активным SHA. Другая установка запрещена до разрешения pending. |
| После завершения, ответ потерян | Повтор того же пакета успешен и сохраняет время/служебные поля. После TTL возвращает текущий unconfirmed, не продвигает доверие. |
| Контрольное чтение неуспешно | Проверяются прежние ресурсы; автоматический CAS-откат возможен только пока state всё ещё ожидаемый. При повреждённой прежней версии остаётся текущая pending-версия для ручной инспекции, повреждённая версия не активируется. |
| Более поздняя публикация или подтверждение | Старый restore/invalidate с несовпадающей ожидаемой ревизией получает конфликт. Не подменяйте ожидаемое значение без инспекции текущего состояния. |

Возврат к worker выполняется отдельно: сначала restore нужного совместимого снимка, проверить GET/HEAD и неизменность URL, затем `owner ... --owner legacy` с актуальным SHA. Изменения реального расписания здесь нет. Прежде чем изменять Cron/среду, будущий оператор должен отдельно подтвердить остановку старого worker, точный runtime bundle, права и актуальный сайт. Ordinary release и rollback проверяют private state fail-closed; publisher-каталог запрещает замену своих PHP/JS consumers без отдельной reviewed миграции. Совместимый UI-релиз допустим, приватный каталог обычный релиз не копирует и не восстанавливает из backup.

## Доказательства и ограничения

`review/r2b/` содержит независимый отчёт с хешами файлов, повторные integration/release-manager логи, E2E JSON с командами и SHA пакетов, фактически скачанные PDF, локальный CI fast и PHP 8.4 contract. SIGKILL проверяется непосредственно до/после записи указателя и после завершения до ответа. Отдельная регрессия сохраняет pending-кандидат при порче старого ресурса и ошибке контрольного чтения. Проверены конкурирующие процессы, неверная база, namespace, порча снимка/плана, неполный пакет, symlink, дополнительные файлы, типы и повтор.

Это проверка штатных PHP/JS-потребителей на loopback PHP server; production Apache/Jino/VPS не запускались. Не проверялись живой источник, фактическая доставка писем/заявок, расписание и установка на хостинг. Полный исторический `ci:full` не является заменой целевой приёмки этого PR; выполненный набор и его результаты записаны явно. Для merge нужны принятый контракт и отдельный GO владельца. Для production потребуется отдельная реализация/приёмка разрешённого пути установки, guarded runtime migration и инфраструктурного переключения.
