# PRICE-SYNC-002 — приёмка перед включением Jino Cron

Разовый релиз `price-sync-002-catalog-20261118` подтверждён на production. Проверки ниже выполняются локально с опубликованной версией и тестовыми снимками. Применение WEBSITE и установка RUNTIME оформляются двумя отдельными разрешениями.

## Каталог и дата

- Если единственное изменение у застройщика — новая квартира с недоступной схемой, проверенные предложения остаются в том же снимке. Во внутреннем состоянии фиксируется `partial`; сообщение для администратора включает номер, ID, причину, официальный URL и версию сохранённого снимка. Успешное повторное получение схемы добавляет квартиру.
- При частичном импорте отсутствующей квартиры публичная страница сохраняет подтверждённые предложения и дату проверки. Служебное сообщение о пропущенном импорте находится в письме и частном состоянии. Если проверка опубликованной квартиры не подтвердилась, календарная дата последней достоверной сверки сохраняется.
- Успешная сверка без изменений цен меняет время проверки в HTML и заголовке HEAD при прежнем идентификаторе снимка. После ошибки видна нейтральная дата последней проверки. Проверки PHP и Chromium используют одну строку рядом с подписью о мебели, в том числе с отключённым JavaScript.
- Тесты отдельно проверяют подозрительные массовые изменения, подмену идентичности, ошибки выгрузки, недопустимый SVG, конкурентный запуск, сбой записи и отказ SMTP с повтором уведомления без повторной публикации.

## Вкладки и форма

- Вкладка с исходным JavaScript релиза от 18 ноября отправляет лот без `lotPrice`. Новый обработчик возвращает `409 catalog_reload_required`, старая форма показывает предложение связаться с агентством. Синтетическое письмо не появляется. Старый локальный PDF возможен, его исходный текст маркирует расчёт как справочный. Уже исполненный JavaScript в этой вкладке заменить можно только перезагрузкой страницы.
- Вкладка, открытая после WEBSITE и до установки RUNTIME, скачивает PDF при совпадении версии и блокирует его после смены версии сайта. Та же проверка действует между двумя активными снимками. Браузерный тест проверяет сумму в калькуляторе, загрузку PDF и сообщение после смены версии. Серверная форма отклоняет устаревшую сумму до отправки.
- При загрузке обновлённой страницы URL двух скриптов каталога содержит хеш собранного файла. Остальная работа по [CACHE-BUSTING-001](https://github.com/AntonZemlya/dom-u-morya/issues/33) остаётся в своём scope.

## Серверный маршрут и производительность

- Изолированные Apache и PHP 8.4 проверяют главную страницу до активации и с частным снимком, canonical, 236 запросов в матрице редиректов, неизменяемые ресурсы, ACME и запрет доступа к приватным путям. SVG и WebP проверяются по реальному маршруту, оригинал сверяется по SHA-256.
- Синтетический обычный релиз и его откат сохраняют частный активный снимок. Откат к прежней статической политике блокируется, пока каталог активен. Для аварийного возврата требуется остановить Cron и сохранить частные данные согласно [инструкции эксплуатации](../../ops/CATALOG-SYNC-RUNBOOK.md).
- Медианы полного ответа в одном локальном Apache составили 0,27 мс для статического маршрута, 1,11 мс для PHP до активации и 3,72 мс при активном снимке. В трёх чередующихся мобильных прогонах Lighthouse обе версии получили 80 баллов. Медиана LCP составила 4726 и 4727 мс соответственно, CLS — 0,003 в обеих версиях. Это измерения в лаборатории. Производственный замер входит в серверную приёмку.

## Приёмка на Jino

1. После GO WEBSITE применить пакет, проверить резервную копию и receipt `verified`. Проверить HTTPS GET/HEAD, PHP-маршрут, текущие 28 лотов, PDF, canonical и ответы API без тестовых заявок. Сопоставить время ответа с текущей версией.
2. После отдельного GO RUNTIME установить частный пакет. Проверить `seed`, `dry-run`, первый реальный цикл, версии и SHA-256 снимка и схем. При прежних ценах активный снимок сохраняется, дата успешной сверки меняется.
3. Отправить одно служебное письмо через `mail-test`, подтвердить его в контрольном ящике. В панели Jino зарегистрировать единственное задание на 08:30 МСК. Подтвердить запуск в журнале и сверить время HEAD сайта. Если Cron вообще не стартует, независимо проверять заголовок последней сверки из существующего мониторинга.
