## Результат

Стрелки теперь привязаны к фактическому прямоугольнику вписанного изображения: на desktop располагаются в тёмных полях рядом с краями фотографии, на mobile — у её боковых границ с минимальным перекрытием. Большие плотные круги заменены лёгкими полупрозрачными дисками. Видимый диаметр с тонким контуром — до **40 px desktop / 36 px mobile**, области нажатия — **48×48 / 44×44 CSS px**. Толщина стрелки **1,25 CSS px** остаётся читаемой при уменьшении SVG благодаря `non-scaling-stroke`. Hover и клавиатурный focus усиливают фон и контур; в светлых областях фотографии и планировки используется тёмная стрелка.

## Алгоритм

1. После открытия, смены кадра, загрузки/декодирования и изменения геометрии берутся intrinsic `naturalWidth/naturalHeight` и фактическая область `<img>` с внутренними отступами слайда. Для подготовленных растров доступен запасной размер из метаданных; для SVG размеры берутся после загрузки. При отсутствии intrinsic-размеров используется безопасная область элемента.
2. Вычисляется масштаб `min(availableWidth / naturalWidth, availableHeight / naturalHeight)`, фактические ширина/высота и центр изображения с `object-fit: contain`.
3. На desktop зона кнопки располагается снаружи кадра с зазором **12 px**; видимый диск находится примерно в **16 px** от края. Если свободного поля viewport не хватает, создаётся только необходимый боковой отступ слайда. Он общий для трёх кадров и не меняется во время свайпа. Вертикальные фото, ограниченные высотой, при этом не уменьшаются. При достаточном поле исходный размер фото сохраняется.
4. На mobile отдельный зазор не создаётся. Кнопки прижимаются к краям изображения и ограничиваются viewport; на самых узких кадрах видимый диск перекрывает максимум около **28 px** у края. Остальная фотография сохраняет прежний размер.
5. Положение по вертикали совпадает с центром самого изображения. Расчёт выполняется через объединённый `requestAnimationFrame` после завершения перехода, а не в `pointermove`. Во время активного жеста и анимации координаты заморожены; zoom/pan их не перемещают. `ResizeObserver` учитывает изменение доступной высоты, а обработчик resize — поворот и смену ширины. Устаревшее завершение decode не может передвинуть стрелки нового кадра. После перехода положение мягко уточняется за 180 мс; при reduced motion переходов нет.

## Геометрия до/после

Измеряется видимый прямоугольник изображения независимо от CSS-переменных приложения. На 1440/390/320 px ни один из пяти видов изображения не уменьшился. На 768 px широкое фото занимает **632 вместо 688 px**: по 28 px с каждой стороны — ровно недостающее место для внешних кнопок. «Лобби» сохраняет прежнюю ширину.

| 768 | Лобби | 578.5 → 578.5 | 48×48 |
