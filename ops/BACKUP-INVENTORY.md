# BACKUP-INVENTORY — публичная версия

Подробный read-only inventory выполнен и передан владельцу локально: точные серверные
пути, account quota, размеры/даты/SHA архивов и receipt metadata не публикуются в GitHub.
Они сохранены отдельным ограниченным по доступу handoff вне Git.

## Разделение копий

| Категория | Управление |
|---|---|
| Встроенные копии Jino | Провайдер; не менять и не удалять в этой задаче |
| Исторические release/backups «Дома у моря» | Только read-only inventory; исключены из executable prune |
| Исторические архивы Rehab Profi | Только read-only аудит; изменения относятся к отдельной задаче |
| Новые release-backups | Только namespace универсального менеджера, manifest + SHA + restore rehearsal |
| Config/runtime/.envrc | Критические данные, private backup 0600/0700; экспорт только шифрованный |
| Mutable state заявок | Отдельный DATA-RETENTION-001 / Issue #18, не release rollback |

Точные кандидаты и ожидаемая экономия находятся в приватном inventory владельца.
Разрешённая очистка в этом PR отсутствует; фактических удалений нет. Похожий размер,
возраст или читаемый tar сами по себе не подтверждают безопасное восстановление.

## Правила провайдера и открытый вопрос

[Справка Jino](https://jino.ru/spravka/hosting/) описывает периодичность копий
2–11 дней (premium 2–6), хранение 20 дней и восстановление выбранных файлов/папок
и MySQL в отдельную папку. [FAQ](https://o.jino.ru/help/faq/mysql-general/restore-backup/)
описывает также восстановление почты. Доступность и фактический состав копии конкретного
аккаунта требуют проверки; production restore в этой задаче не запускался.

**C2 — UNCONFIRMED/BLOCKED для полной приёмки:** изученная официальная справка не
подтверждает однозначно учёт встроенного backup storage в shared-hosting quota.
Нужен договор/ответ Jino; обращение не отправлялось. Не подменять account limit
размером серверного раздела или общим рекламным тарифом. Менеджер требует свежие
panel limit/usage и использует их вместе с home allocation и запасом свободного места.
