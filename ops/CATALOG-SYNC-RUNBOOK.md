# Ежедневный каталог на Jino

## Границы релиза

PRICE-SYNC-002 использует собственное расписание Jino и один атомарно переключаемый снимок. PHP отдаёт HTML для главной страницы с актуальными карточками, начальными суммами калькулятора и SEO-разметкой. Браузер получает те же квартиры и цены внутри страницы. Форма читает этот снимок при каждом запросе на квартиру и возвращает 409, если цена или наличие изменились. Открытая страница проверяет свою версию перед выгрузкой PDF. В режиме без JavaScript карточки и цены остаются в HTML.

Обработчик главной страницы работает с новым точным SHA-256 политики Apache. Штатный менеджер проверяет переход с v3 и публикует правило маршрутизации после обработчика и шаблона. Пока частный каталог отсутствует, обработчик отдаёт проверенные байты пакета. Активный ответ сверяется с SHA шаблона и внутренней согласованностью HTML и SEO. Файлы частного каталога находятся вне web-root. При штатных релизах и откатах с совместимой политикой Apache эти файлы сохраняются.

## Установка после владельческого GO

1. Из проверенного коммита собрать пакет штатным менеджером. Для релиза нужны свежая квота панели Jino, штатный preflight, точный план и отдельный GO для `release apply`. Дождаться receipt `verified`.
2. На том же коммите собрать частный пакет командой `python3 -B ops/catalog_sync_runtime.py build --commit COMMIT --release-id RELEASE_ID --website-sha PACKAGE_SHA --output RUNTIME_JSON`. Команда выведет отдельную строку разрешения установки и активации с SHA обоих пакетов.
3. После получения точного разрешения выполнить локально `python3 -B ops/catalog_sync_runtime.py install-remote --bundle RUNTIME_JSON --runtime-sha SHA --go "EXACT_GO"`. Менеджер передаст утверждённый пакет по SSH и выполнит установщик из памяти. Установщик проверяет receipt текущего релиза, хеш и точный набор файлов, затем устанавливает частный пакет. При потере ответа сначала проверить `installed.json`.
4. Выполнить `seed`, `run --dry-run`, `run` и `status`. `seed` использует опубликованные проверенные планировки и сохраняет дату исходного снимка. Проверить по HTTPS главную страницу, версию снимка и хотя бы одну оригинальную схему и WebP. Проверить `mail-test` и поступление письма на действующий контрольный адрес, заданный веб-формой. Тест создаёт служебное уведомление об автоматизации. Данные покупателей для этого не нужны.
5. В разделе **Настройки веб-сервера → Задания по расписанию** панели Jino создать одно задание `Дом у моря — ежедневная сверка каталога`. Часовой пояс сервера MSK, выражение `30 8 * * *`. Сохранить команду ниже. Верифицировать запись в панели и запуск по расписанию по времени в `status`, журналу заданий и заголовкам ответа сайта.

```sh
/bin/sh /home/users/j/j84938826/.dom-u-morya/catalog-sync-v1/runtime/scripts/catalog-cron.sh
```

Панель управляет Cron. В SSH-оболочке считывание `crontab -l` вернуло ошибку адаптера CloudLinux, тогда как панель отображает действующие задачи. Для запуска рабочей команды подтверждены Python 3.6, PHP 8.4, Node 22 по абсолютному пути, ImageMagick и исходящий HTTPS.

## Запуск и проверка

На Jino рабочий каталог размещён в `~/.dom-u-morya/catalog-sync-v1`. Для ручной проверки используйте скрипт из `runtime/scripts`.

```sh
cd ~/.dom-u-morya/catalog-sync-v1/runtime
/usr/bin/python3 -B scripts/catalog_sync.py run --dry-run
/usr/bin/python3 -B scripts/catalog_sync.py run
/usr/bin/python3 -B scripts/catalog_sync.py status
```

`status` показывает версию и размер каталога, время последней проверки, доступные снимки, до 30 последних событий и размер очереди писем. Снимки хранятся в `snapshots/`, оригиналы и превью в `media/`, активная версия и очередь в `state.json`. Хранятся до шести используемых версий. Для удаления осиротевших изображений действует суточный запас для открытых страниц. Хранилище планировок ограничено 180 МиБ.

Скрипт сверяет полный список дважды и проверяет индивидуальные карточки. Скачивает схемы с указанных в карточках URL и хранит их по SHA-256. При неизменных ETag или Last-Modified сервер возвращает 304. При отсутствии этих заголовков файл перепроверяется раз в шесть дней. Серьёзные несогласованности сохраняют последнюю рабочую версию с предупреждением об актуальности. Проблема одной схемы оставляет соответствующее предложение на уточнении или откладывает добавление. Если сутки обновления пропущены, по истечении 36 часов сайт отмечает актуальность цен как неподтверждённую.

Письма о публикации и ошибках отправляются через действующий SMTP-транспорт на адрес `CONTROL_MAILBOX_VERIFIED`. Повтор не меняет активную версию. При потере финального подтверждения SMTP возможно повторное письмо с тем же Message-ID. Пустой результат в штатном запуске не вызывает отправки. Обёртка Cron сообщает планировщику о ненулевом завершении процесса и пытается зафиксировать таймаут в состоянии проекта. Если планировщик вообще не запустил команду, остаются журнал Jino и отметка актуальности на сайте.

## Остановка и восстановление

Отключите только задание сверки в панели Jino. Дождитесь завершения текущего запуска. Для восстановления просмотрите `status` и укажите подтверждённую предыдущую версию.

```sh
/usr/bin/python3 -B scripts/catalog_sync.py restore --version SNAPSHOT_SHA
```

Восстановление сохраняет предыдущий снимок и помечает цены как требующие подтверждения до новой сверки. Для обычного отката к совместимому релизу применяется штатный менеджер. Откат к статическому релизу до появления серверного каталога блокируется, пока действует частный снимок. Для аварийного возврата к статическому сайту после остановки Cron сначала получите отдельное разрешение владельца, сохраните в приватном архиве весь каталог и примените штатный план отката. Перед повторным включением выполните полную сверку.
